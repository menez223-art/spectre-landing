## ١. الهدف

تمكين الزائر (الڤيست) من تجربة المنصّة عبر **رابط حقيقي واحد** لمدة **24 ساعة**
دون اشتراك مسبق، مقابل **إيميل + رقم واتساب**، ثم **حرق الرابط نهائياً** إن لم
يشترك خلال المدة. الهدف: خفض عائق التجربة + التقاط بيانات تواصل حقيقية + إلحاح.

## ٢. القواعد النهائية (قرارات المالك)

| # | القاعدة |
|---|---|
| ١ | تسجيل الإيميل **بلا رمز تحقّق** |
| ٢ | **رابط واحد فقط** لكل **إيميل** — ولكل **جهاز** — ولكل **رقم واتساب** |
| ٣ | منتج **واحد** بصورة **واحدة** |
| ٤ | **بدون HTML** (لا GitHub) و**بدون Google Sheets** |
| ٥ | الطلبات تذهب إلى **واتساب الڤيست فقط** |
| ٦ | بعد 24 ساعة: **حرق نهائي** — لا مهلة، ولا بيانات متبقية |
| ٧ | **الحذف اليدوي** قبل الانتهاء يمنع رابطاً جديداً (نافذة تأكيد إلزامية) |
| ٨ | إن كان الإيميل **مشتركاً أصلاً** ← لا تجربة، بل توجيه لتسجيل الدخول |
| ٩ | **رقم الواتساب إجباري** — تُرسل إليه الطلبات التجريبية (لافتة توضّح ذلك) |
| ١٠ | المدة **قانونية وثابتة: 24 ساعة** — **لا تمديد زمني إطلاقاً** |
| ١١ | التحويل لدائم: الأدمن **يُعيّن اشتراكاً** فيتغيّر status المستخدم ويصبح الرابط دائماً |
| ١٢ | اللافتة: **عربي + إنجليزي فقط** (لا فرنسية)، ونصّها **يتبع لغة الصفحة** التي يختارها الزائر |
| ١٧ | **لا يُنشأ الرابط حتى تكتمل خانات المنتج** (الاسم · السعر · الصورة · العنوان · الوصف · مميزة واحدة) **والإيميل والواتساب** — مفروض على **٣ طبقات** (الواجهة · اللوحة · الخادم) |
| ١٨ | زر التجربة **أول عنصر** في لوحة الڤيست (بارز، بلا تمرير) |
| ١٣ | **الزائر يرى اللافتة والعدّاد** (لا صاحب الرابط فقط) |
| ١٤ | رقم الواتساب **داخلي فقط** — لا يظهر كزر تواصل للزائر |
| ١٥ | الحرق = **حذف نهائي من قاعدة البيانات**، ويخصّ **روابط الڤيست فقط** — لا يُمسّ أي رابط مشترك |
| ١٦ | المهمة المجدولة: **توسعة القائمة** (`link-health?action=auto`) لا مهمة جديدة |

> **الخلاصة:** التجربة **مرة واحدة للأبد**. للحصول على أخرى: إيميل جديد + جهاز جديد.
> ولا يوجد «تمديد» — إمّا **اشتراك خلال 24 ساعة** أو **حرق**.

## ٤. بنية التخزين (مقترح)

بادئة جديدة في `KV_PREFIXES`:

```
TRIALS = "trials/"
```

### ٤.١ السجل الأساسي (يبقى للأبد)

```jsonc
// المفتاح: trials/<email>.json
{
  "email": "user@example.com",
  "whatsapp": "2135XXXXXXXX",   // إجباري
  "deviceFp": "<بصمة مملَّحة>",
  "slug": "a1b2c3d4e5",
  "createdAt": "ISO",
  "expiresAt": "ISO",
  "status": "active",           // انظر الحالات
  "burnedAt": null,
  "deletedAt": null,
  "convertedAt": null
}
```

### ٤.٢ فهارس الهوية (جهاز + واتساب)

```jsonc
// المفتاح: trials-device/<deviceFp>.json
{ "email": "user@example.com", "slug": "a1b2c3d4e5" }

// المفتاح: trials-whatsapp/<أرقام فقط>.json
{ "email": "user@example.com", "slug": "a1b2c3d4e5" }
```

> **تطبيع الرقم (مهم):** `+213 555 11 11 11` و `00213555111111` و `213555111111`
> تُوحَّد كلها إلى `213555111111` عبر `normalizeWhatsapp()` — وإلا تهرّب المستخدم
> من قيد «مرة واحدة» بمجرد تغيير التنسيق. (مُختبَر: يُرفق بصيغة مختلفة ✓)

> عند الحرق يُحذف **بيانات المنتج فقط** (`published/<slug>.json` +
> `published-meta/<slug>.json`). السجل وفهرس الجهاز يبقيان لفرض «مرة واحدة للأبد».

## ٧. التدفقات

### ٧.١ الإنشاء
```
الڤيست → إيميل (إجباري) + واتساب (إجباري) + منتج (صورة واحدة)
      → تحقّق (٧ شروط)
      → buildTrialProduct() + نشر (بلا sheet، بلا GitHub)
      → Product.whatsapp = رقم الڤيست
      → trialUntil = الآن + 24 ساعة
      → سجل + فهرس جهاز
```

### ٧.٢ اللافتة أثناء التجربة (عربي + إنجليزي)

ثلاثة عناصر مجتمعة:

1. **نص واضح:** «هذا نموذج تجريبي — يُحذف نهائياً بعد انتهاء المدة»
2. **عدّاد تنازلي:** الوقت المتبقي بالساعات والدقائق
3. **زر بارز:** «اشترك الآن» ← يوجّه إلى **`/pricing`** لاختيار باقة مباشرة

> الزر يظهر في **صفحة الڤيست (لصاحب الرابط)** لا للزائر النهائي،
> أمّا الزائر فيرى اللافتة التعريفية فقط. *(يحتاج تأكيد المالك)*

### ٧.٣ الحرق — الشرح المبسّط

المسألة: **من يحذف الرابط بعد 24 ساعة؟**

| الطريقة | الشرح |
|---|---|
| **أ) عند الزيارة** | أول شخص يفتح الرابط بعد انتهاء المدة ← نحذفه فوراً. ✅ بسيط وفوري |
| **ب) مهمة يومية** | تمسح الروابط المنتهية التي **لم يزرها أحد** — وإلا بقيت للأبد تستهلك مساحة |

> **كلتاهما مطلوبة:** (أ) للسرعة، و(ب) للروابط المهجورة.
> **مقترحي:** توسعة المهمة المجدولة القائمة (`/api/admin/link-health?action=auto`)
> بدل إنشاء مهمة جديدة — لتجنّب حدّ عدد المهام في خطة Vercel.

### ٧.٤ التحويل إلى دائم (بيد الأدمن فقط)

الأدمن يفتح نافذة التجارب ← يختار **اشتراكاً** (basic / gold / pro …) للمستخدم:
```
ensureSubscription(email, plan)  →  status المستخدم يتغيّر
حذف trialUntil من published-meta →  الرابط يصبح دائماً
السجل: status = "converted"
```
> **لا يوجد تمديد زمني** — إمّا اشتراك فعلي أو حرق.
